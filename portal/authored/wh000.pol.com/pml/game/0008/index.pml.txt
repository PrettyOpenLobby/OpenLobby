	  pol-server AUTHORED PAGE, ARCHIVAL. FINAL FANTASY XIV IS a registered
	  PlayOnline content -- id 8, `FINALFANTASY_XIV`, dated **2009/10/27** -- but
	  only in the XBOX 360 Viewer family. Found in the mirrored patch tree
	  X2U-1000, build 20091222_A (work/ps2/mirrors, .slc blob, decrypted with the
	  int0 key like every other sqpolcts.bin).

	  IT IS ABSENT FROM EVERY PC AND PS2 BUILD WE HOLD -- the 2003 CD, JP 1.15,
	  JP preupdate, PS2, W2U-1000, EU, JP 2011 and US 1.18 tables all jump 7 -> 10.
	  The two families diverge: the Xbox table carries id 8 and no id 15, while
	  the 2011 PC tables carry id 15 (FINALFANTASY_XI_TEST) and no id 8.

	  The PC side did ship the ART: the red "XIV" badge is in cicn_s002 tile 0 of
	  the us-2011 and jp-2011 sheets (blank in jp-preupdate, EU and FriendList;
	  the 2003 CD has no sheet 2 at all). So on PC the icon arrived without the
	  registration -- which is why an earlier version of this page wrongly said
	  the content was "never registered". It was, on Xbox, two years earlier.

	  Its record flag is 0, the same as EverQuest II and the mail services, and
	  unlike every title the Viewer actually launches (FFXI, TM, Mahjong, FMO, DC,
	  FE are all 1) -- consistent with a portal/account registration rather than a
	  launchable content. FFXIV shipped on the Square Enix account system.

	  WHAT THE ICON IS FOR. The cicn_* sheets are the per-handle content BADGES:
	  app.dll walks each handle character list, resolves every entry, and feeds
	  the resulting u16 content code to the icon getter to pick the tile it draws
	  beside that handle. Selection is by NUMBER and never consults this table, so
	  on a PC client -- which has the tile but not the record -- an id 8 badge
	  would still draw, while the title itself would resolve to the polcore
	  fallback name "Contents0008".

	  INFORMATIONAL ONLY -- no Play button, nothing installable.
	  References NO server-hosted images: one HTTP request.
	-->
